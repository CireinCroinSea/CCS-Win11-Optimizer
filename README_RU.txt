Win11 Gaming Optimizer — универсальный проект Windows 11 x64
Автор: cireincroinsea

НОВЫЙ ИНТЕРФЕЙС:
Твики расположены списком; справа у каждой строки есть кнопки «Включить/Очистить» и «Сбросить».
Убраны кнопки, которые только открывали настройки Windows. Диагностика остаётся отдельной кнопкой.

СБОРКА EXE:
1. Установи .NET 8 SDK x64: https://dotnet.microsoft.com/en-us/download/dotnet/8.0
2. Распакуй архив целиком.
3. Запусти `Собрать_EXE.bat` (в архиве также оставлен `Build_EXE.bat`).
4. EXE появится в publish\Win11GamingOptimizer.exe; после успешной публикации временные папки bin и obj удаляются автоматически.

ВАЖНО:
- Программа запрашивает права администратора для системных твиков.
- Автоматические резервные копии не создаются.
- Сброс параметра реестра удаляет значение и возвращает системное поведение по умолчанию; исходное вручную заданное значение не восстанавливается.
- Очистка кэша шейдеров может временно усилить статтеры до повторной компиляции.
- HAGS и NetworkThrottlingIndex не гарантируют улучшение FPS/пинга; меняй их по одному и измеряй frametime. Профиль против микрофризов больше не пишет спорные значения MMCSS.
- Ultimate Performance может повысить нагрев и энергопотребление; сброс переключает на стандартный Balanced.
- Defender, брандмауэр, Windows Update, критические службы и VBS/HVCI не отключаются.


Дополнительно: пункт «Телеметрия Windows» устанавливает политику AllowTelemetry=0. На домашних редакциях Windows часть политик может применяться ограниченно; это не отключает всю диагностику Windows.


ПРОВЕРКА ВЕРСИИ / ОГРАНИЧЕНИЯ:
- Архив включает диагностические эвристики (свободное место, сетевые счётчики, строки событий WHEA/видеодрайвера/дисков и краткий ping-тест). Это подсказки для проверки, не точный диагноз и не игровой бенчмарк.
- Ограничение ScanAvgCPULoadFactor для Defender влияет на среднюю загрузку CPU при сканировании, а не является жёстким лимитом; реальная поддержка зависит от состояния Defender и прав.
- Цвет нативной полосы прокрутки задаётся Windows и `SetWindowTheme` поддерживается не всеми WinForms-контролами одинаково; произвольный акцентный цвет не гарантируется.
- Код нацелен на .NET 8 Windows Forms x64. В этой среде нет Windows/.NET SDK для полноценной сборки и запуска GUI; перед использованием проверь `Собрать_EXE.bat` на Windows.
- Запуск с повышенными правами необходим для многих системных настроек. Запись рядом с EXE может быть заблокирована, если папка лежит в `Program Files`; используй обычную папку приложения.

ЖУРНАЛ ДЕЙСТВИЙ:
- Новая вкладка «Журнал» показывает действия и ошибки программы.
- Файл истории находится рядом с EXE: Отчёты\Журнал_действий.log.
- Журнал можно экспортировать; очистка отображения не удаляет файл истории.
- В журнал попадают операции менеджера автозагрузки, а также ошибки включения/отключения записей.
- См. GITHUB_REVIEW_RU.md: идеи открытых проектов, которые были рассмотрены; исходный код не копировался.

НОВЫЕ РАЗДЕЛЫ:
- «Состояние ПК» — снимок загрузки CPU, использования ОЗУ и свободного места на дисках.
- «Температуры» — показывает доступные стандартные ACPI-зоны, если Windows их предоставляет. Это не гарантированный датчик CPU/GPU; для аппаратных датчиков есть ссылка на LibreHardwareMonitor.
- «Сеть» — скорость получения/отдачи в Мбит/с и МБ/с, общий объём трафика и состояние адаптера. Скорость считается по разнице сетевых счётчиков.
Главная страница при запуске — «Состояние ПК».


Дополнительная библиотека датчиков: LibreHardwareMonitorLib (NuGet). При первой сборке требуется интернет для восстановления NuGet-пакетов.


Учёт сетевого трафика по процессам
Вкладка «Сеть» использует ETW (события TCP/IP ядра Windows) для подсчёта байтов по PID и показывает суммарные MB, входящую/исходящую скорость и сортирует процессы по суммарному объёму. Счётчики начинают собираться при открытии вкладки и сбрасываются при её повторном открытии. Для ETW нужны права администратора; если сбор событий недоступен, текст ошибки появится в списке. Это не полный системный учёт трафика до запуска вкладки.
