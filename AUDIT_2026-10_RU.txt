АУДИТ Win11 Gaming Optimizer — 09.10.2026

Что проверено в исходниках:
- структура ZIP проекта, csproj, manifest и BAT-файлы;
- обработка путей реестра, сохранение журнала конфигурации и состояний кнопок;
- обработка системных команд, плана питания и ошибок запуска;
- профиль HARD и его сброс;
- Game Mode/Game DVR: подтверждение и симметричный сброс;
- диагностика дисков, сетевых счётчиков, ping и системных событий;
- Windows Update, настройка CPU сканирования Defender, менеджер автозагрузки и тема интерфейса.

Исправлено в этой версии:
1. Нормализация старых путей реестра с двойными обратными слешами.
2. RunCommand теперь читает stdout/stderr параллельно, имеет 8-секундный тайм-аут, останавливает зависший процесс и возвращает ненулевой код завершения вместо скрытия ошибки.
3. Переключение плана питания проверяется по фактически активному GUID; сброс HARD возвращает «Сбалансированный» и сообщает о частичном сбое.
4. Исправлено описание профиля против микрофризов: MMCSS больше не изменяется при применении; при сбросе старые MMCSS-значения удаляются только как остатки прошлой версии. Ошибки сброса больше не скрываются молча.
5. Game Mode сбрасывает оба значения, которые оно устанавливает. Apply/reset для Game Mode и Game DVR используют одно подтверждение на операцию вместо нескольких подряд.
6. Сброс возвращает лимит средней загрузки CPU Defender при сканировании к стандартным 50% (если командлет доступен и не блокируется политиками).
7. Добавлен этот отчёт об аудите; русское имя Build-файла находится рядом с англоязычным, оба файла совпадают.

Ограничения и что важно понимать:
- Проект нацелен на .NET 8 WinForms x64 и публикуется self-contained для Windows x64. .NET 8 по состоянию на 09.10.2026 ещё поддерживается, но поддержка заканчивается 10.11.2026; последняя опубликованная исправленная версия — 8.0.31. Для долгосрочного обновления стоит планировать переход на .NET 10 LTS, но он не включён в этот архив, чтобы сохранить совместимость с установленным у пользователя .NET 8 SDK.
- В среде, где выполнялся аудит, нет Windows/.NET SDK, поэтому компиляцию и запуск GUI выполнить не удалось. Проверены исходники и целостность ZIP, но это не заменяет сборку на Windows. Запусти Собрать_EXE.bat; перед массовым использованием сначала проверь на одном компьютере.
- Windows Update: NoAutoUpdate=1 — поддерживаемая политическая настройка автоматического обновления, а не гарантированный блокировщик всех механизмов обновления и напоминаний. Поведение зависит от редакции Windows, MDM/групповых политик и обслуживания ОС. Обновления безопасности придётся проверять вручную.
- Defender: ScanAvgCPULoadFactor=20 задаёт ориентир средней CPU-нагрузки движка во время сканирования, а не жёсткий лимит, не отключает realtime-защиту и может игнорироваться в некоторых сценариях ручного сканирования или других настройках. Сброс ставит 50, если cmdlet применим.
- Темы и полосы прокрутки: SetWindowTheme меняет источник визуального стиля контрола; Windows не гарантирует конкретный цвет нативной полосы прокрутки для каждого контрола и редакции. Если полоса «Игры»/автозапуска остаётся белой на конкретной сборке Windows, нужно воспроизвести на этой системе и при необходимости рисовать собственную полосу прокрутки, а не обещать исправление одним вызовом API.
- Переключатель состояния сохраняет визуальное состояние кнопки, а не доказывает, что реальное системное значение всё ещё применено. Диагностика явно так и пишет.
- Английская локализация частичная: некоторые описания и диагностические сообщения остаются на русском.
- Менеджер автозагрузки не эквивалентен Task Manager: обрабатывает известные записи Run и папки Startup, а не абсолютно все запланированные задачи/службы/modern startup entries.
- Диагностические сигналы эвристические. Пять ping-проб до 1.1.1.1 не измеряют игровой сервер; сетевые error counters накопительные; Win32_DiskDrive.Status не заменяет SMART; поиск по тексту журналов даёт предварительный сигнал. Нет обнаруженных признаков ≠ гарантированно нет проблем.
- Нет автоматических резервных копий, как и просил пользователь. Удаление значений обычно возвращает контроль Windows по умолчанию, но не возвращает кастомное значение, установленное до оптимизатора, если оно не было записано отдельно.

Оценка пользы:
- Полезны: отчёт диагностики как отправная точка, контроль состояния Windows Update, ограничение CPU фонового сканирования Defender при подтверждённых сканированиях во время игры, выбор плана питания, очистка временных файлов с предупреждениями.
- Условны и требуют A/B теста: HAGS, Power Throttling, NetworkThrottlingIndex, отключение фоновых приложений, Ultimate Performance, SysMain и Windows Search.
- Не рекомендованы как рутинная «оптимизация FPS»: регулярная очистка кэша шейдеров, выключение SysMain/Windows Search без симптомов, массовое применение всех твиков. Очистка shader cache может сначала увеличить статтеры, а отключение служб может ухудшить обычную работу Windows.
- Для проверки игрового эффекта меняй по одному параметру и сравнивай одинаковую сцену/длительность через frametime (например, PresentMon/CapFrameX), а не только средний FPS.

Итоги проверки системных функций:
- Game Mode — штатная настройка Windows; Microsoft указывает, что большинство игр используют её по умолчанию. Отдельный выигрыш для каждой игры не гарантируется.
- HAGS, Ultimate Performance, Power Throttling и NetworkThrottlingIndex не являются универсальными ускорителями; сравнивать следует на одной сцене по frametime. NetworkThrottlingIndex помечен как старый параметр без обещания снижения пинга.
- SysMain и Windows Search меняли только тип запуска службы в реестре, но не останавливали уже работающий сервис. Тексты карточек это теперь уточняют; отключение без конкретной проблемы не рекомендуется.
- Добавлены переходы к системной графике для отдельной игры и к режиму питания Windows 11. Это штатные настройки, без новых изменений реестра.
- Удалён вводящий в заблуждение текст о сохранении приоритета игры: AboveNormal применяется только к уже запущенному процессу и исчезает после его закрытия.
- Очистка корзины и кэша Delivery Optimization теперь проверяет успешный результат PowerShell и показывает ошибку вместо ложного успеха. Для Delivery Optimization вызывается штатный Delete-DeliveryOptimizationCache.

Ограничения сброса сохраняются: существующие вручную заданные параметры реестра и выбранный до оптимизатора план питания не резервируются автоматически; часть сбросов возвращает Windows к типичному значению, а не к индивидуальному OEM/пользовательскому состоянию. Кнопка «Сбросить все» и HARD-профиль требуют осторожности.
